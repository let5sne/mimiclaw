# 硬件自调试方案与备件清单

## 背景

当前硬件项目的主要问题，不是软件完全不会调试，而是缺少稳定的外部感知与执行闭环：

- 看不到设备屏幕显示
- 看不到面包板接线和机械动作
- 不能稳定采集串口、供电和复位状态
- 不能自动完成“修改 -> 刷机 -> 重启 -> 观测 -> 比对”这一轮回归

为了解决这些问题，可以先搭建一套“一期半自治调试平台”。平台目标不是完全自动修好所有硬件问题，而是尽可能把问题发现、复现、验证修复这三个环节自动化。

---

## 核心结论

增加摄像头和两自由度舵机云台后，系统可以从“盲调”升级到“半自治调试”，但还不能直接等同于“完全自主修复”。

### 能显著提升的能力

- 自动观察屏幕是否点亮、黑屏、花屏、卡死
- 自动识别屏幕文字、错误提示、状态页变化
- 自动观察指示灯、继电器、机械动作是否符合预期
- 自动执行多轮复测，判断修改后问题是否仍然复现
- 自动对比前后图像，发现明显接线松脱、装配偏差、位置错位

### 仍然无法单靠摄像头和云台解决的问题

- 重新插拔杜邦线、重接面包板、焊接、换器件
- 发现被遮挡、被线束覆盖、角度不可见的接线错误
- 稳定识别虚焊、接触不良、地弹、电源跌落、时序抖动
- 修复纯物理故障、器件损坏、机械卡死等问题

结论可以概括为一句话：

> 摄像头 + 云台主要解决“看见”和“复测”，不能单独解决“动手修”。

---

## 适合本项目的一期方案

一期建议优先实现以下闭环：

1. 相机观察屏幕、面包板和执行机构
2. 串口抓取目标板日志
3. 自动刷写固件并触发测试
4. 通过继电器或可控电源完成远程断电重启
5. 自动比对屏幕状态、日志和传感器数据

这样做的目标是让软件可以独立完成以下流程：

1. 下发固件或参数修改
2. 自动刷机
3. 自动重启被测设备
4. 自动切换相机视角并采集图像
5. 自动读取串口日志与电源状态
6. 输出“问题复现 / 未复现 / 疑似修复 / 需要人工检查”的结论

## 推荐备件清单

以下清单按“一期可落地闭环”给出，默认被测目标板为 ESP32 系列。

### 必需件

- `Raspberry Pi 5 8GB` x1
  - 作为调试主机，负责视觉采集、舵机控制、串口抓取、自动刷机和测试编排
- `树莓派官方 27W USB-C 电源` x1
  - 只给树莓派供电，不与舵机共用
- `microSD 64GB A2` x1
  - 用于系统、日志和测试脚本
- `Raspberry Pi Camera Module 3` x1
  - 安装在云台上，负责近距离观察屏幕、插线细节和局部动作
- `Raspberry Pi Camera Module 3 Wide` x1
  - 固定俯视，用于观察整块面包板、屏幕周围和全局状态
- `两自由度云台 + S20F 舵机` x1 套
  - 负责多角度巡检
- `PCA9685 PWM 驱动板` x1
  - 用于稳定控制双舵机
- `6V 5A 以上独立舵机电源` x1
  - 建议直接使用 `6V 8A`，避免双舵机启动或堵转时拖垮系统
- `INA226 电压/电流监测模块` x2
  - 一个监测舵机供电，一个监测被测板供电
- `2 路继电器模块` x1
  - 用于控制被测板断电重启
- `USB 转串口模块` x1
  - 用于采集目标板日志
- `ESP-Prog` x1
  - 如果目标板不自带方便的下载/JTAG能力，建议加入

### 强烈建议

- `环形补光灯` 或 `柔光 LED 灯条` x1
  - 提升 OCR 和图像对比稳定性
- `硬质支架 / 铝型材框架` x1
  - 固定云台、面包板、屏幕和相机位置
- `ArUco / AprilTag 标记纸` 若干
  - 便于自动标定视角与坐标
- `杜邦线标签、扎带、线槽` 若干
  - 降低线束遮挡和误判
- `独立保险丝模块或电源开关模块` x1
  - 防止故障时拖垮整套调试平台

### 一期暂不建议采购

- 机械夹爪、机械臂
  - 这是“物理修复”阶段，不是一期开销重点
- 高端示波器自动联动方案
  - 后续可以扩展，但一期先把视觉、供电、日志闭环跑通
- 复杂 AI 相机方案
  - 一期优先保证视角稳定和数据链路可靠

## 云台和舵机使用建议

你当前考虑的两自由度云台适合做“观察机构”，不适合直接承担“修复机构”。

### 适合的用途

- 看屏幕是否正常刷新
- 看 LED、继电器、蜂鸣器等状态变化
- 看舵机、机构、按键是否真正执行到位
- 查看某一段接线是否松脱或移位

### 需要特别注意的问题

- 双舵机必须使用独立供电，不能直接吃树莓派 5V
- 树莓派电源和舵机电源必须共地，否则控制信号不稳定
- 必须设置软限位，避免撞结构、缠线或超角度拉扯
- 相机线缆和舵机线缆要做防缠绕设计
- 视角必须可重复，最好配合固定参考点做标定

## 我负责的软件范围

当以上硬件准备完成后，软件侧可以由我负责以下部分：

### 1. 云台与设备控制

- 双舵机控制
- 预设视角位管理
- 视角扫描与自动巡检
- 防抖等待与稳定拍照
- 继电器控制与远程重启

### 2. 视觉诊断

- OCR 读屏
- 黑屏、花屏、卡屏检测
- 指示灯状态识别
- 接线区域变化检测
- 关键区域截图留档与前后比对

### 3. 调试自动化

- 自动刷机
- 自动串口采集
- 自动执行回归测试脚本
- 自动记录测试轮次、镜头位、日志片段和判定结果

### 4. 问题闭环

- 自动输出“是否复现”
- 自动输出“修复后是否通过”
- 自动区分“软件问题优先”与“疑似硬件问题”
- 自动生成调试报告，提示需要人工介入的位置

## 装配红线

为了避免平台本身不稳定，装配时至少遵守以下约束：

- 树莓派供电和舵机供电分开
- 所有控制地线必须共地
- 不要让双舵机直接由面包板电源模块供电
- 不要通过继电器直接粗暴断开树莓派本体电源
- 相机、云台、被测板位置尽量固定，避免每次测试姿态都变化
- 被测板电源路径和日志路径要明确，便于自动定位异常

---

## 建议的下一步

建议按以下顺序推进：

1. 先采购并装好一期必需件
2. 固定云台、面包板、屏幕和俯视相机位置
3. 打通树莓派到目标板的串口、刷机、继电器控制链路
4. 完成相机标定和预设观察位
5. 开始实现“自动巡检 + 自动复测”的第一版软件闭环

---

## 一句话总结

这套方案的目标，不是让系统立刻变成会自己焊线和换器件的机器人，而是先把它变成一个能够**自己观察、自己复测、自己判断是否修复**的硬件调试平台。
